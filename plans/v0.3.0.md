# v0.3.0: Bounded lifecycle

**Milestone**: [v0.3.0](https://github.com/mainvec/procman/milestone/1)
**Issues**: #22, #23, #24, #25, #26

## Goal

A supervisor built on procman can shut down within a deadline, run indefinitely
without retaining every command it ever started, and rely on Windows Job Objects
to contain the whole tree. The API stops advertising behaviour procman does not
have.

mainvec/zirafa is the driving consumer. It upgrades once, to v0.3.0
(mainvec/zirafa#187), after this release.

## API summary

Added:

```go

func WithAutoRemove() ExecCmdOption             // #23

func (c *ExecCmd) StopContext(ctx context.Context) error     // #24

func (p *Procman) ShutdownContext(ctx context.Context) error // #24

```

Removed (#22): `RestartPolicy`, `RestartPolicyNever`, `RestartPolicyAlways`,
`RestartPolicyOnFailure`, `WithRestartPolicy`.

Unchanged: `Stop`, `StopAll` and `Shutdown` keep their signatures and behaviour,
as `context.Background()` wrappers.

## Decisions

- **A cancelled stop escalates.** When a context ends before the stop completes,
  procman force-kills the command and its tracked tree, then returns an error
  wrapping `ctx.Err()` without waiting for reaping. A deadline on a stop means
  the caller cannot wait any longer; leaving the process running would only
  move the problem. One caller's expiry escalates a stop that other callers
  share, and those callers still receive the final result.
- **Removal waits for the tree.** `Remove` refuses while the direct child runs or
  its tree is tracked, because `StopAll`, `KillAll` and `Shutdown` find
  commands through the registry. A removed command that never started cannot
  start, so no child ever runs outside the registry's reach.
- **The stop signal is Unix-only.** Windows has no group-addressable alternative
  to `CTRL_BREAK_EVENT`, so the option fails at command creation there rather
  than being silently ignored.
- **Windows resumes with documented APIs.** The initial thread is found with a
  Toolhelp thread snapshot rather than the undocumented `NtResumeProcess`. The
  spike (#29, results on #26) confirmed the mechanism. With a 200ms
  creation-to-assignment window, a grandchild spawned at the child's first
  instruction escaped the job in 6 of 6 runs without suspended start, and was
  inside it in 6 of 6 with it. The snapshot covers every thread on the system,
  so a resume costs 9–17ms on a CI runner (about 1,600 threads), and more on a
  busier machine. That is paid only by commands with a Job Object.
  `NtResumeProcess` would cost microseconds; it remains the fallback if the
  snapshot cost proves too high.

## Out of scope

- **#27 Unix watchdog for parent-death cleanup.** This is a design issue with no
  milestone.
- **Restart policies.** They are removed, not deferred. Supervisors restart
  commands themselves, using `OnExit` and `TreeDone`.
- **Event-driven tree tracking.** It still polls; neither platform offers an exit
  notification for a group or job procman is not the parent of.
